# CLAUDE.md

Монорепо VPN-клиента: Flutter-приложение (Android, Windows), Go-ядро туннеля на sing-box (Android: gomobile, Windows: служба `vpnsvc`), Go-бэкенд с Telegram-ботом поверх Remnawave, инфраструктура на Ansible и Docker Compose.

## Источник истины

@tech.md

`tech.md` — замороженное ядро проекта. Подчиняйся ему дословно. Если этот файл и `tech.md` расходятся, прав `tech.md`.

## Перед началом работы

1. Назови версию ядра, против которой работаешь (строка «Версия ядра» в `tech.md`).
2. Определи слайс: ID из имени ветки (`gh-42-s1-08-...`) или из задачи пользователя. Нет ID — спроси, не угадывай.
3. Прочитай карточку слайса в `tech.md` §16 и эталонную вертикаль §15.2. Раскладку файлов и тестов копируй с эталона.
4. Стадия 0 не закрыта (чек-лист §15.3 не зелёный) — фичи стадий 1+ не начинай.

## Жёсткие правила

- Один слайс за раз. Сфокусированный дифф только в путях своего слайса.
- Контракты не выдумывай. Нет типа, поля, эндпоинта, kind'а River, метода IPC, ключа настройки, роута или UI-примитива → СТОП и блок `CONTRACT GAP` по шаблону `tech.md` §13. Код с выдуманным типом не пиши.
- Контрактные пути (`tech.md` §5.1) не правь, если пользователь явно не дал задачу `contract-change`.
- Generated-код (`*/gen/**`, `backend/internal/db/sqlc/**`, `core/internal/contract/**`) руками не правь. Только `make gen`.
- Миграции не пиши.
- Фичи app зависят только от `VpnBridge`, не от Pigeon или named pipe напрямую. Платформенные ветки только в `app/lib/core`.
- Свайп между экранами режимов только переключает экран. Режим туннеля меняет только тап по `PowerButton` (`tech.md` §2.1).
- Экраны собирай только из примитивов `app/lib/ui`. Цвета и размеры только из токенов. Примитивы работают на тач и мыши.
- Пользовательские строки app только через l10n, сразу ru и en. Тексты бота — в `messages_ru.go`.
- Секреты не коммить и не логируй: `uuid`, пароли Hysteria2, токены устройств, коды входа, токен бота.

## Тесты

- Сначала тесты из критериев приёмки карточки, потом код. Тест кодирует контракт, не зеркалит реализацию.
- Обязательно по `tech.md` §10: контрактный тест на стыке, идемпотентность каждого джоба и обработчика апдейтов бота, путь ошибки через фейк, property-based на чистой логике (Go: rapid, Dart: glados).
- Если установлен skill `engineering:testing-strategy`, используй его для плана тестов.

## Команды

```
make dev            # Postgres в Docker, бэкенд с PANEL_MODE=fake и TELEGRAM_MODE=fake, сид; код входа в логе
make gen            # все генераторы: OpenAPI -> Go/Dart, Pigeon, sqlc
make check          # формат, линт, analyze, vet, gen без диффа
make test           # все тесты
make seed           # сид-данные в локальную БД
make core-android   # .aar через gomobile
make core-windows   # vpnsvc.exe
make installer      # установщик Inno Setup (только на Windows)
```

App без устройства и без службы: `--dart-define-from-file=env/dev.json` с `FAKE_VPN=true`.

## Коммиты и PR

- Всё на английском: коммиты, PR, комментарии в коде.
- Коммит: `type(scope): summary`, `type` из `feat|fix|test|refactor|chore|docs`, `scope` из `app|android|windows|core|backend|bot|contracts|infra|ci`. Императив, со строчной, без точки, до ~50 символов.
- Коммить сам по ходу работы, маленькими логическими шагами, каждый коммит проходит анализатор.
- PR: заголовок в формате коммита с номером GitHub Issue (`tech.md` §19.3), тело по `tech.md` §12, включая `Core: tech.md vN`. Для android/windows — результат ручного чека.
- Комментарии объясняют почему. Закомментированный код не оставлять.

Выполнен Definition of Done из `tech.md` §14 и `make check && make test` зелёные.
