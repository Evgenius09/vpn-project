# Дизайн приложения: с чего начать

Документ для того, кто берётся за внешний вид клиента. Состояние на 2026-11-03, ядро `tech.md` v25.

## Где проект сейчас

Приложение работает. На реальном Android-телефоне через настоящий сервер в Стокгольме проверены вход через Telegram-бота, подключение и выбор сервера. Пинг, экран «Белые списки» и автопереход на белые списки при смене сети сделаны и покрыты тестами, на телефоне отдельно не проверялись. Тестовую сборку раздают друзьям (`docs/testers.md`).

Внешнего вида пока нет: стоит Material 3 по умолчанию и временные цвета. Визуальный дизайн по плану приходит отдельно (`tech.md` §2.1).

## Запуск без телефона, сервера и VPN

Фейковый API отдаёт тестовый профиль с пятью серверами и пускает с любым ником и любым кодом. Фейковый VPN изображает подключение, отключение и трафик.

```
cd app
flutter run --dart-define-from-file=env/design.json            # Windows-десктоп или эмулятор Android
```

На Linux и macOS десктоп-сборки нет: приложение собирается только под Android и Windows (`tech.md` §1).

Все компоненты в светлой и тёмной теме уже отрисованы картинками в `app/test/ui/goldens/`. С них удобно начать. Экран-витрина `/dev/kitchen-sink` есть в debug-сборках, но кнопки входа в него в приложении пока нет.

## Как устроен внешний вид

Одно правило: **редизайн = замена токенов и компонентов, экраны не трогаются** (`tech.md` §2.1, §8). Экраны собраны только из компонентов `app/lib/ui`, а компоненты берут цвета, отступы и шрифты только из токенов. Поменяли токен или компонент, и поменялись все экраны.

| Что | Где |
|---|---|
| Цвета светлой и тёмной темы: `bg`, `surface`, `surfaceAlt`, `primary`, `onPrimary`, `text`, `textMuted`, `success`, `warning`, `danger`, `connected`, `connecting`, `idle`, `border` | `app/lib/ui/tokens.dart`, `AppColors` |
| Отступы 4–48, радиусы 8/12/20/pill, шрифты display/title/body/label/caption, длительности анимаций, размеры иконок, ширина контента 480 | `app/lib/ui/tokens.dart` |
| Тема Material 3 из токенов, режим system/light/dark | `app/lib/ui/theme.dart` |
| Компоненты: `PowerButton`, `ModePager`, `PageDots`, `ServerSheet`, `ServerTile`, `PingBadge`, `FlagIcon`, `StatusBanner`, `TrafficCounter`, `CodeInput`, `Settings*Tile`, `AppButton`, `AppTextField`, `AppDialog`, `AppSnack`, `EmptyState`, `LoadingView`, `ErrorView` | `app/lib/ui/primitives/` (полный список с параметрами — `tech.md` §8) |
| Тексты на русском и английском | `app/lib/l10n/app_ru.arb`, `app_en.arb` |

Своих шрифтов и картинок нет: системный шрифт, иконки Material, флаги стран — эмодзи.

## Экраны и их состояния

1. **Вход** (`app/lib/features/auth`): ник Telegram → код из бота с таймером повторной отправки и кнопкой «Открыть бота»; экран «Откройте бота и нажмите Start», если бот вас не знает; ошибки с числом оставшихся попыток.
2. **Главный** (`app/lib/app/home_screen.dart`): два экрана-режима, «Обычный VPN» и «Белые списки», листаются свайпом, точками `PageDots` и стрелками ← →. На каждом: кнопка настроек, `PowerButton` со статусом и таймером, баннер ошибки или смены режима, трафик, выдвижной список серверов с пингом и тумблером «сортировать по пингу». На «Белых списках» ещё тумблер автоперехода на мобильной сети.
3. **Настройки** (`app/lib/features/auth/settings_screen.dart`): пока минимальные — тумблер автоперехода и выход из аккаунта. Полные настройки — слайс S3-01.

Состояния кнопки `PowerButton`: `idle`, `connecting`, `connected`, `disconnecting`, `error`. На экране неактивного режима при подключённом туннеле кнопка в `idle` с подписью «Сейчас активен: …» (таблица в `tech.md` §2.1).

## Чего держаться

- **Свайп только переключает экран.** Подключение и смена режима — только тап по `PowerButton`.
- Цвета и размеры — только из токенов, никаких чисел и цветов в экранах.
- Каждый компонент работает пальцем и мышью: наведение, фокус с клавиатуры.
- Обе темы: светлая и тёмная.
- Windows: окно 420×760, минимум 360×640, контент по центру шириной до 480.
- Новый текст — сразу в оба файла `.arb`, русский и английский.
- Нужен новый компонент или экран — сначала он появляется в `app/lib/ui` и в таблице `tech.md` §8.

## Как сдавать работу

- `app/lib/ui` — контрактный путь: PR с меткой `contract-change` и строкой в `tech.md` с новой версией ядра (`tech.md` §5.1, §13). Без этого проверка `contract-guard` в CI красная.
- Картинки компонентов обновляются на Linux, потому что шрифты рендерятся по-разному на разных системах (`tech.md` §19.4):

  ```
  cd app
  flutter test --update-goldens --tags golden
  ```

  Новые PNG из `app/test/ui/goldens/` коммитятся в тот же PR.
- Перед PR: `make check && make test` из корня.
